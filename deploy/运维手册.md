## 4. 更新上线(改了代码后)

**方式 A — 本地一键脚本(推荐)**,在本地 git bash 执行:
```bash
bash f:/advancedweb/pj/.deploy/redeploy.sh
```
它会:上传最新源码 → 服务器重建镜像 → 滚动重启。

**方式 B — 手动**:本地先上传源码,再到服务器重建:
```bash
# 本地(git bash),在 Superior_Web_tech_project 目录:
tar czf - --exclude=node_modules --exclude=dist --exclude=.angular --exclude=.git \
  --exclude=logs --exclude=run-logs --exclude=temp --exclude=data \
  --exclude=backend/target --exclude='__pycache__' . \
  | ssh -i ~/.ssh/deploy_2395 root@23.95.186.11 'tar xzf - -C ~/mlplatform'

# 服务器:
cd ~/mlplatform && docker compose -f docker-compose.prod.yml up -d --build
```

> 只改了某一个服务时,可只重建它:`$DC up -d --build backend`。
> 更新后清理旧镜像省磁盘:`docker image prune -f`。

## 5. 数据备份与恢复

数据都在卷 `mlplatform_backend-data` 里(H2 文件库)。

**备份**(导出为 tar 到 `~/backup`):
```bash
mkdir -p ~/backup
docker run --rm -v mlplatform_backend-data:/data -v ~/backup:/b alpine \
  tar czf /b/db-$(date +%F-%H%M).tgz -C /data .
ls -lh ~/backup
```

**恢复**(从某个备份还原,会覆盖现有数据):
```bash
cd ~/mlplatform && docker compose -f docker-compose.prod.yml stop backend
docker run --rm -v mlplatform_backend-data:/data -v ~/backup:/b alpine \
  sh -c "rm -rf /data/* && tar xzf /b/db-2026-06-22-1200.tgz -C /data"
docker compose -f docker-compose.prod.yml start backend
```

**下载备份到本地**:
```bash
scp -i ~/.ssh/deploy_2395 root@23.95.186.11:~/backup/db-*.tgz .
```

> 建议:定期(如每天)跑一次备份,可用 crontab 自动化(见第 6 节)。

## 6. 监控与健康检查

```bash
# 容器健康(python 配了 healthcheck,看 STATUS 列的 healthy)
docker compose -f docker-compose.prod.yml ps

# 资源占用
docker stats --no-stream
df -h /                      # 磁盘

# 链路自检(在服务器上)
curl -s -o /dev/null -w "%{http_code}\n" http://localhost/            # 前端 应为200
curl -s http://localhost/api/algorithms | head -c 120                 # API 应返回JSON
docker exec mlplatform-python-1 curl -s http://localhost:8000/internal/health  # python 应返回 ok
```

**每天自动备份(可选)**,服务器上 `crontab -e` 加一行:
```
0 3 * * * docker run --rm -v mlplatform_backend-data:/data -v /root/backup:/b alpine tar czf /b/db-$(date +\%F).tgz -C /data . && find /root/backup -name 'db-*.tgz' -mtime +7 -delete
```
(每天 03:00 备份,保留最近 7 天)

## 7. 日志管理(防磁盘撑满)

Docker 默认日志无上限,长期运行会撑满磁盘。建议限制日志大小:

服务器编辑 `/etc/docker/daemon.json`:
```json
{
  "log-driver": "json-file",
  "log-opts": { "max-size": "10m", "max-file": "3" }
}
```
然后 `systemctl restart docker && cd ~/mlplatform && docker compose -f docker-compose.prod.yml up -d`。
(每个容器最多 3×10MB 日志,自动滚动)

手动查看磁盘占用:`docker system df`;清理无用数据:`docker system prune -f`(谨慎,会删未使用的镜像/网络)。

## 8. 故障排查

| 现象 | 排查 / 处理 |
|---|---|
| 网页打不开 | `$DC ps` 看 frontend 是否 Up;`curl localhost` 在服务器上自测;查 ufw 是否放行 80 |
| 网页能开但功能报错 | 多半是后端:`$DC logs --tail 100 backend`;`curl localhost/api/algorithms` |
| 训练无响应 | 看 python:`$DC logs --tail 100 python`;`$DC ps` 看 python 是否 healthy |
| 502 Bad Gateway | 后端没起来或正在重启:`$DC ps`、`$DC logs backend`,等其启动完成 |
| 某容器反复重启 | `$DC ps` 看 Restarting;`$DC logs <服务>` 找报错;改完 `$DC up -d --build <服务>` |
| 磁盘满 | `df -h`、`docker system df`;清日志(第7节)+ `docker image prune -f` |
| 改了代码没生效 | 必须 `--build` 重建镜像:`$DC up -d --build`(只 restart 不会重新编译) |
| 数据丢了 | 从 `~/backup` 恢复(第5节);确认没误删卷 `mlplatform_backend-data` |

**全量重启大法**(多数问题先试这个):
```bash
cd ~/mlplatform && docker compose -f docker-compose.prod.yml restart
```

## 9. 安全维护

- **改 root 密码**(密码曾在聊天暴露,务必改):`passwd`
- **关闭 SSH 密码登录**(只留密钥):编辑 `/etc/ssh/sshd_config` 设 `PasswordAuthentication no`,然后 `systemctl restart ssh`(确保密钥可用后再关)。
- **系统更新**:定期 `apt update && apt upgrade -y`。
- **防火墙**:`ufw status` 检查;只开放必要端口。
- **绑域名 + HTTPS**(进阶):用 Caddy 或 nginx+certbot 自动签发证书,把 http 升级为 https。
- 不要把 8080/8000 用 `ports:` 暴露公网;保持现在的 `expose:` 内网模式。

## 10. 重启与灾难恢复

- **服务器重启后**:Docker 自启 + 容器 `restart=always` → **自动全部恢复**,无需手动操作。
- **手动全部拉起**:`cd ~/mlplatform && docker compose -f docker-compose.prod.yml up -d`
- **从零重建**(换服务器):装 Docker → 上传源码到 `~/mlplatform` → `docker compose -f docker-compose.prod.yml up -d --build` → 从备份恢复数据卷(第5节)。
- **回滚**:Docker 不自动留旧版本镜像。如需可回滚,更新前先打标签:
  `docker tag mlplatform-backend:latest mlplatform-backend:backup` ,出问题再 `docker tag` 切回并 `up -d`。
